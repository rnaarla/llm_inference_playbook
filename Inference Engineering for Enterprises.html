Notation

n is context length in tokens. L is the number of layers. d is head dimension. K is a fixed KV budget in tokens. The KV footprint of one sequence is L × 2 × n_kv_heads × d × bytes × n; section T2 computes it. Complexity in context length is written O(n), never O(L), so that layers and length are not confused.

What a verification date means

A figure marked verified 2026-11-04 was checked against its primary source on that date: the paper, the vendor documentation, or a computation in the repository. T1

Systems Layer: Lossless, Deploy Today

WhenAlways. No model change. Captures the 2–4× engine baseline before any other optimization is attempted.
PerformanceMemory

Serve on a modern engine

Deploy on vLLM or SGLang rather than a hand-rolled generate loop. PagedAttention, continuous batching, chunked prefill and fused attention kernels ship on by default. The vLLM paper reports 2–4× throughput over FasterTransformer and Orca at equal latency verified 2026-11-04; that is the baseline every later optimization is measured against.

In the vLLM V1 engine, preemption defaults to recompute rather than CPU swap, and chunked prefill is enabled by default wherever the model supports it verified 2026-11-04. Design tiering around the KV connector interface (section 04), not around swap space.

Prefix sharing with a radix tree

Enable RadixAttention (SGLang) or vLLM's prefix caching for workloads with shared prefixes: agents, few-shot prompting, multi-turn chat, tree-of-thought search. The tree performs longest-prefix match at any branch point with no manual breakpoints and no TTL. The SGLang paper reports up to 6.4× throughput against vLLM-based and guidance-based baselines on its agentic and few-shot benchmarks verified 2026-11-04.

Engine-side prefix sharing and provider-side prompt caching (T5) are not substitutes. The engine feature exists only when you run the engine. Provider caching exists only when you do not. A deployment that mixes self-hosted and hosted models needs both, and section E1 applies to both: in a multi-tenant deployment, the cache key must include the tenant.

Block-based allocation

PagedAttention reduces KV fragmentation and reservation waste from the 60–80% the vLLM paper measured in prior systems to under 4% verified 2026-11-04. The reclaimed HBM converts into batch size at identical hardware. It does not shrink the useful bytes of any sequence; only architecture and precision (T2) do that.

Shrink the KV Cache: Bytes Per Token

WhenHighest-leverage layer. Decode is bandwidth-bound, so KV bytes translate directly into time per output token.
MemoryPerformanceAdvanced

Architecture: GQA or MLA over vanilla MHA

Grouped-Query Attention divides KV bytes by the ratio of query heads to KV heads. Llama-3-8B uses 32 query heads and 8 KV heads, a 4× reduction over an MHA checkpoint of the same geometry verified 2026-11-04. DeepSeek's Multi-head Latent Attention caches a low-rank latent instead of per-head K and V; the DeepSeek-V2 paper reports a 93.3% KV reduction and 5.76× generation throughput against DeepSeek 67B, its MHA predecessor verified 2026-11-04. Both are paid once at checkpoint selection and never at runtime, which is why P ranks them second.

Precision: FP8 then INT4

KIVI quantizes keys per channel and values per token, matching the different outlier structure of the two tensors. The paper reports 2.6× peak memory reduction, up to 4× batch size, and 2.35–3.47× throughput against its FP16 baseline with near-zero quality loss on its benchmarks verified 2026-11-04. Validate on your task at each step (section M, gate G7–G9); ship the lowest precision that clears the gate, not the lowest that runs.

Composition is multiplicative, and attributed separately

Architecture, precision and retention attack orthogonal factors. On Llama-3-8B at 32K context: the checkpoint's own FP16 cache is 4 GiB. Against a 16 GiB MHA cache of the same layer count and head dimension (Llama-2-7B geometry), GQA contributes 4×, INT4 contributes 4×, and SnapKV at 25% retention contributes 4×, for 64× in total and a final cache of 256 MiB. From the checkpoint's own baseline the runtime factors give 16×. The earlier edition of this page stated a 128× figure on Llama-2-7B with "GQA-8"; Llama-2-7B is an MHA model and has no group ratio to apply, so that figure was not reproducible. The function below is what the test suite runs.

Pythonbudget.py · kv_bytes
def kv_bytes(
    arch: Architecture,
    seq_len: int,
    bits: int = 16,
    retention: float = 1.0,
) -> int:
    """Exact KV footprint for one sequence.

    bits encodes precision (16 | 8 | 4). retention encodes the eviction policy
    (1.0 means no eviction). Architecture is a property of the checkpoint and
    is paid once at model selection, never at runtime.
    """
    if bits not in (16, 8, 4):
        raise ValueError("bits must be 16, 8 or 4")
    if not 0.0 < retention <= 1.0:
        raise ValueError("retention must be in (0, 1]")
    per_token = arch.n_layers * arch.kv_width() * (bits / 8)
    return int(per_token * seq_len * retention)
Pythonbudget.py · attribute
def attribute(
    arch: Architecture,
    mha_baseline: Architecture,
    seq_len: int,
    bits: int,
    retention: float,
) -> Attribution:
    """Reduction attributable to each factor, reported separately.

    The three factors are orthogonal and compose multiplicatively. Report them
    separately: a single blended multiple hides which layer did the work and
    invites double-counting against engine-level savings (PagedAttention
    removes reservation waste, not useful bytes; it belongs in neither factor).
    """
    base = kv_bytes(mha_baseline, seq_len)
    arch_only = kv_bytes(arch, seq_len)
    final = kv_bytes(arch, seq_len, bits, retention)
    return Attribution(
        architecture_x=base / arch_only,
        precision_x=16 / bits,
        retention_x=1 / retention,
        total_x=base / final,
        baseline_bytes=base,
        final_bytes=final,
    )

Attack the Time Dimension

WhenLatency-critical single-stream traffic, or long shared prefixes that outlive HBM residency.
PerformanceI/O

Speculative decoding

EAGLE and Medusa reduce the number of serial decode steps by drafting several tokens and verifying them in one forward pass. The transformation is lossless: the output distribution is provably identical to standard sampling. EAGLE reports 2.7–3.5× latency reduction against vanilla autoregressive decoding on LLaMA2-Chat 70B in its benchmarks verified 2026-11-04.

Gate rollout on acceptance length and batch size. Speculation trades extra compute for fewer sequential steps, so the gain shrinks toward zero once the GPU is compute-saturated by a large batch, and goes negative when acceptance falls (section O5, "speculation inversion"). Measure acceptance on production traffic; the paper's benchmark distribution is not yours.

Tiered KV across the memory hierarchy

Mooncake and LMCache extend the KV cache beyond HBM through DRAM, NVMe and RDMA-attached memory. Effective cache capacity grows by one to two orders of magnitude. The Mooncake paper reports up to 525% throughput improvement in simulated scenarios on replayed traces under its latency SLOs, and a 75% increase in handled requests on real workloads verified 2026-11-04. Sections 01 through 10 are the implementation of this tier hierarchy; section A1 covers the prefill/decode disaggregation that Mooncake pairs it with.

Change the Asymptotics

WhenExact recall is optional. Lossy by construction. Requires the quality gate in O6 before production.
AdvancedTesting

Bounded cache through eviction and sparsity

StreamingLLM, H2O and SnapKV bound the cache at a fixed budget of K tokens, converting KV space from O(n) in context length to O(K), constant in n. H2O reports up to 29× throughput against DeepSpeed Zero-Inference and 3× against FlexGen on OPT models verified 2026-11-04. StreamingLLM reports up to 22.2× speedup against the sliding-window-with-recomputation baseline verified 2026-11-04. Neither baseline is a modern paged engine, so expect smaller multiples against T1.

Appropriate for streaming and chat where distant tokens are not needed. Do not apply to exact-recall workloads (long-document QA, code comprehension, legal analysis) without the gate in O6, and do not operate it without the rollout controls in O4, because an eviction policy an adversary can steer through prompt construction is also an attack surface (E4).

Hybrid state-space architectures

Mamba and Mamba-attention hybrids replace the linearly growing KV cache with a constant-size recurrent state: O(n) prefill, O(1) decode step, O(1) space in n. This is an architecture decision made at model selection, not a runtime flag. The compression into a fixed state is where these models can fail on recall; validate with needle-in-a-haystack at every depth you intend to serve.

Prompt and API Discipline

WhenAlways, including on hosted providers where no engine-level control exists. Zero infrastructure cost.
PerformanceObservability

Order stable to volatile

Prefix caching ends at the first changed token. That is a prompt-layout decision, not a physical constraint. Invariant content first; per-request entropy last.

Quantize volatile fields; version the key

Round timestamps to the hour. Serialize tool definitions through a deterministic sort. Make model identity, tokenizer version and adapter identity part of the cache key so that keys stay stable across benign changes and invalidate on meaningful ones. In a multi-tenant deployment the tenant is part of the key as well; section E1 gives the implementation.

Sticky routing

Engine and provider caches are per worker. Route a session to the same backend or hit rates collapse regardless of prompt layout. Section O2 lists this as the second most common cause of a hit-rate collapse, after a template regression.

Break-even economics

The repository's cost.py computes break-even from the provider's multipliers rather than embedding a rate. For a provider that bills a cache write at 1.25× the input price and a read at 0.1×, the cached path is cheaper from the second use onward: (1.25 − 0.10) / (1 − 0.10) = 1.28 uses. Anthropic's documented multipliers for the 5-minute cache were 1.25× write and 0.1× read, with a 2× write for the 1-hour cache verified 2026-11-04; Gemini bills explicit cache storage as a token-hour product on top of discounted reads, and the rate was not re-verified for this edition. Re-check both before committing.

Pythoncost.py · cache_break_even_reuses
def cache_break_even_reuses(p: HostedPrice) -> float:
    """Reuses after which a cached prefix is cheaper than resending it.

    Writing costs W = write_multiplier, each later read costs R = read_multiplier,
    resending costs 1 each time. After n uses the cached path costs W + (n-1)R
    and the uncached path costs n. Break-even where W + (n-1)R = n.
    With W=1.25, R=0.10: n = (1.25 - 0.10) / (1 - 0.10) = 1.28, so the second
    use already pays back. Time-billed storage is added separately.
    """
    w, r = p.cache_write_multiplier, p.cache_read_multiplier
    if r >= 1.0:
        return float("inf")
    return (w - r) / (1 - r)
Re-verify at deployment

Separate allocated from useful KV

Quality gates on every lossy change

E1

Tenant-Scoped Cache Keys

WhenAny deployment serving more than one tenant, legal entity or data classification through one engine or one provider account.
SecurityMemory

The exposure

Prefix caches key on token sequences. If the key space is shared, a cache hit is observable as a TTFT difference of tens to hundreds of milliseconds, so tenant A can test whether tenant B has recently submitted a given prefix. In a regulated setting that is a cross-tenant information channel. Separately, a cache that mixes tenants cannot attribute its contents, so per-tenant quotas (E3), deletion requests (E2) and incident scoping (O5) all become impossible.

The control

The tenant is part of the cache key, together with model identity, tokenizer version and adapter identity. Two identical token prefixes from different tenants never collide. Sharing across tenants is an explicit, audited opt-in through a named sharing group, never a default.

Pythontenancy.py · CacheScope
@dataclass(frozen=True)
class CacheScope:
    """Everything that must match for two prefixes to be allowed to share KV."""

    tenant_id: str
    model_id: str  # weights identity, e.g. the checkpoint digest
    tokenizer_version: str
    adapter_id: str = "base"  # LoRA or other adapter; different adapters produce different KV
    sharing_group: str | None = None  # explicit opt-in group; None means tenant-private

    def namespace(self) -> str:
        who = self.sharing_group if self.sharing_group is not None else f"tenant:{self.tenant_id}"
        return "|".join((who, self.model_id, self.tokenizer_version, self.adapter_id))
Pythontenancy.py · prefix_key
def prefix_key(scope: CacheScope, token_ids: list[int], secret: bytes) -> str:
    """Keyed hash of (scope, tokens).

    The HMAC secret prevents a tenant from computing another tenant's keys even
    with knowledge of the namespace format; it is a per-deployment secret, not
    per-tenant. Hash input is the exact token sequence, so a prefix match is a
    byte-identical match: no normalization, no case folding.
    """
    h = hmac.new(secret, digestmod=hashlib.sha256)
    h.update(scope.namespace().encode())
    h.update(b"\x00")
    h.update(len(token_ids).to_bytes(4, "big"))
    for t in token_ids:
        h.update(int(t).to_bytes(4, "big", signed=False))
    return h.hexdigest()

Where it is enforced

  • Self-hosted engines. vLLM and SGLang keep one prefix namespace per engine process. Enforce scope at the gateway by routing tenants to tenant-dedicated replicas, or by prepending a tenant-specific, non-user-controllable token sequence to every prompt so that the engine's own prefix match cannot cross tenants. The second is cheaper; the first is the only option when tenants require memory isolation as well as key isolation.
  • Hosted providers. Caches are scoped to the API key or organization. One shared key across tenants is one shared cache. Use per-tenant keys or per-tenant workspaces where the provider offers them.
  • Tiered stores (01, 04). Blocks spilled to DRAM, CXL or NVMe carry the tenant in their metadata so that E2 can find and delete them.
Irreversible to skip
A cache that has already mixed tenants cannot be separated after the fact; it can only be flushed. This is why P ranks tenant scoping first, before the engine is even chosen.
E2

KV Cache at Rest: Encryption, Retention, Deletion

WhenAny tier below HBM. KV blocks are a lossy-but-reversible function of user tokens and are user data for compliance purposes.
SecurityI/O

What a spilled KV block is

A KV block is the model's internal representation of a span of a user's prompt. It is not plaintext, but it is derived from plaintext by a known function with known weights, and research has shown that inputs can be partially reconstructed from intermediate activations. Treat it as the data it was computed from. The moment a block leaves HBM for DRAM, CXL or NVMe (sections 01, 04, 10), user data has been written to a medium with a lifetime longer than the request.

Retention and deletion

Set a TTL on every persisted block equal to the longest session you support, not the longest you have seen. The deletion job runs per tenant and reports blocks deleted and blocks found past TTL (the second number should be zero; a nonzero value is an alert). A deletion request from a tenant is satisfied by deleting the tenant's blocks in every persistent tier and flushing the tenant's namespace from the prefix cache, then verifying that a read of any deleted block ID fails. Gate G12 (O6) requires evidence of this.

Boundary
CXL memory pooling and remote KV stores move user data across host boundaries. In a FedRAMP or similar authorization, the pool controller and the KV store are inside the authorization boundary and inherit its controls. A tiering design that was not reviewed against the boundary diagram is not ready to ship.

Fairness under pressure

When the degradation ladder (O3) reaches the shedding rung, shed by priority class, then by the tenant furthest over its quota, and log each shed decision with tenant and reason. A tenant that is shed while within quota is an incident; a tenant shed while over quota is the system working. The difference is only visible if the quota and the shed decision are both recorded.

Isolation levels

  • Key isolation (E1). Shared replicas, tenant-scoped cache keys. Sufficient for most commercial tenancy.
  • Memory isolation. Dedicated replicas per tenant or per data classification. Required where a tenant's contract or a regulator prohibits co-residency of data in the same process memory.
  • Host isolation. Dedicated hosts, no CXL pooling with other tenants. Required where side channels at the hardware level are in scope.

Adversarial robustness of cache policies

Two policies in this playbook can be steered by an adversary who controls prompts. Attention-score eviction (07) keeps tokens the model attends to; a prompt constructed to draw attention away from a span can cause that span to be evicted, degrading recall of exactly the content an attacker wants forgotten. Prefix caching can be used for the timing probe described in E1, and a tenant that floods the cache with unique prefixes degrades hit rate for everyone (E3 quotas are the mitigation). Capacity Model

Inputs

def plan(arch: Architecture, gpu: GPU, weights_bytes: int, wl: Workload, bits: int = 16,
         retention: float = 1.0, reserve_fraction: float = 0.10, dram_headroom: float = 1.5) -> CapacityPlan:
    reserve = int(gpu.hbm_bytes * reserve_fraction)
    kv_budget = gpu.hbm_bytes - weights_bytes - reserve
    if kv_budget <= 0:
        raise ValueError("weights plus reserve exceed HBM; shard or quantize weights first")

    p50 = int(np.percentile(wl.seq_lens, 50)) + wl.output_tokens_mean
    p95 = int(np.percentile(wl.seq_lens, 95)) + wl.output_tokens_mean
    kv50 = kv_bytes(arch, p50, bits, retention)
    kv95 = kv_bytes(arch, p95, bits, retention)

    # Expected resident bytes at target concurrency, using the empirical distribution.
    per_seq = np.array([kv_bytes(arch, int(n) + wl.output_tokens_mean, bits, retention) for n in wl.seq_lens])
    expected_total = float(per_seq.mean()) * wl.concurrency
    spill = max(0.0, 1.0 - kv_budget / expected_total) if expected_total > 0 else 0.0

    # Decode reads all weights and all resident KV once per step.
    resident_kv = min(expected_total, kv_budget)
    step_bytes = weights_bytes + resident_kv
    tpot_floor_ms = step_bytes / (gpu.hbm_bandwidth_gbps * 1e9) * 1e3

    return CapacityPlan(
        weights_bytes=weights_bytes,
        reserve_bytes=reserve,
        kv_budget_bytes=kv_budget,
        kv_per_seq_p50=kv50,
        kv_per_seq_p95=kv95,
        resident_at_p50=kv_budget // kv50,
        resident_at_p95=kv_budget // kv95,
        spill_fraction_at_target=spill,
        dram_tier_bytes=int(max(0.0, expected_total - kv_budget) * dram_headroom),
        decode_tpot_floor_ms=tpot_floor_ms,
    )

Outputs that drive decisions

  • resident_at_p50, resident_at_p95. How many sequences fit if they are all median-length, and if they are all 95th-percentile length. The gap between the two is why a fixed max_num_seqs is wrong for a bursty context distribution.
  • spill_fraction_at_target. The share of target concurrency that cannot be HBM-resident. Above roughly 10%, tiering (01) is load-bearing rather than optional; above 50%, the GPU is undersized for the workload.
  • dram_tier_bytes. The next tier's size with headroom, derived from the spill, not guessed.
  • decode_tpot_floor_ms. The bandwidth-bound lower limit on one decode step at target concurrency: weights plus resident KV, divided by HBM bandwidth. If this exceeds the TPOT SLO (C2), the SLO is unattainable at that concurrency on that GPU, and no runtime tuning will change it.

def derive(req: ProductRequirement, queue_share: float = 0.25) -> SLO:
    """TTFT budget is the perceived-start budget less the share reserved for queueing.
    TPOT follows from the reading rate. E2E composes the two for a typical response."""
    ttft = int(req.perceived_start_ms * (1 - queue_share))

    return SLO(ttft, tpot, e2e, req.availability_target, budget_min)

The inputs that decide the answer

  • Measured utilization. Self-hosted cost per token is inversely proportional to utilization. A replica pool sized for peak and idle at night runs at 30–40% utilization and costs two to three times its nameplate figure per token. Use the utilization you have measured, not the one in the business case.
  • Tokens per second at the SLO, not peak. Throughput at a stated p99 TPOT is typically a fraction of the throughput at saturation. Section 19 produces this number.
  • Cached-prefix fraction. On hosted providers, cache reads at 0.1× the input price make the effective input rate a function of prompt layout (T5). A 60% hit rate on input tokens is a large part of the hosted bill.
  • Fully loaded GPU-hour. Instance price, or amortized capital plus power, space, networking, and the people who operate it. The operations layer in O1 through O6 is not free; it is part of this number.

Decision rule

Self-hosting wins when sustained utilization is high, the context distribution is long (the hosted bill scales with input tokens, the self-hosted bill with resident bytes), and the tenancy or boundary requirements (E2, E4) rule out a shared provider. Hosted wins when traffic is spiky, the team cannot staff the operations layer, or the model needed is only available hosted. Run the model with your numbers; the rule is a sanity check on its output, not a substitute for it.

Prefill/Decode Disaggregation

WhenMixed workloads where long prefills stall decode tails, or where prefill and decode want different hardware.
PerformanceAdvanced

Two phases, two bottlenecks

Prefill is compute-bound: a long prompt saturates the tensor cores and produces one KV cache. Decode is bandwidth-bound: each step reads the weights and all resident KV to produce one token per sequence. Co-locating them on one replica means every long prefill delays every decode step scheduled behind it (chunked prefill bounds this; it does not remove it), and means both phases run on hardware sized for the other.

The pattern

Prefill replicas compute the KV cache and transfer it to decode replicas over a high-bandwidth interconnect (RDMA, NVLink across a node, or a shared KV store). Decode replicas hold many resident sequences and run bandwidth-bound steps with no prefill interference. DistServe reports up to 7.4× more requests served within latency SLOs, or 12.6× tighter SLOs at the same request rate, versus co-located serving on its benchmarks verified 2026-11-04. Mooncake (T3) is this architecture in production at scale, with the tiered KV store as the transfer medium.

Mixture-of-Experts Considerations

WhenServing an MoE checkpoint. Most frontier open-weight models now are, and the memory system changes shape.
MemoryAdvanced

What changes

In a dense model, decode reads all weights once per step and the KV cache is the growing part of memory. In an MoE model, each token activates a few experts out of many, so the weights are much larger than the compute suggests, and the per-step weight read is a function of how many distinct experts a batch activates. The KV cache per token is set by the attention geometry exactly as in T2 (MoE changes the feed-forward layers, not attention, so a GQA or MLA MoE has the same KV per token as its dense counterpart).

Invariants the tier manager must hold

The earlier edition of this class had three defects that would corrupt accounting in ordinary operation: it charged the destination tier the compressed size after decompressing into it, it subtracted the compressed size from a source tier that had been charged the uncompressed size, and it never checked capacity on demotion. The rewrite below holds four invariants, and tests/test_tiers.py checks each, including under four concurrent threads.

  1. tier_usage[t] equals the sum of stored_nbytes of blocks resident in t, where stored_nbytes is the size in the block's current form (compressed or not).
  2. Every move computes the destination form and size first, then checks destination capacity, then commits. A refused move changes nothing.
  3. All mutation is under one lock. The prefetcher (08) calls promote from worker threads.
  4. A block's payload type is tracked explicitly. Nothing calls .nbytes on bytes.

Pythontiers.py · TieredKVCache.move
def move(self, block_id: int, target: Tier) -> bool:
    """Move a block between any two tiers. Returns False if target lacks room.

    Form in the target tier follows the target's codec: an identity codec
    means resident uncompressed; any other codec means resident compressed.
    Size is computed in the target form *before* the capacity check, so the
    check is evaluated against the bytes that will actually land.
    """
    with self._lock:
        block = self.blocks[block_id]
        if block.tier == target:
            return True
        src_codec = self.configs[block.tier].codec
        dst_codec = self.configs[target].codec
        dst_cfg = self.configs[target]

        # Compute the target form without yet committing it.
        want_compressed = not isinstance(dst_codec, IdentityCodec)
        if want_compressed and not block.compressed:
            new_k = dst_codec.compress(to_bytes(block.k))  # type: ignore[arg-type]
            new_v = dst_codec.compress(to_bytes(block.v))  # type: ignore[arg-type]
        elif not want_compressed and block.compressed:
            new_k = from_bytes(src_codec.decompress(block.k), block.k_shape, block.dtype)  # type: ignore[arg-type]
            new_v = from_bytes(src_codec.decompress(block.v), block.v_shape, block.dtype)  # type: ignore[arg-type]
        elif want_compressed and block.compressed and dst_codec is not src_codec:
            # Re-encode across codecs: decompress with source, compress with target.
            new_k = dst_codec.compress(src_codec.decompress(block.k))  # type: ignore[arg-type]
            new_v = dst_codec.compress(src_codec.decompress(block.v))  # type: ignore[arg-type]
        else:
            new_k, new_v = block.k, block.v
        new_size = (len(new_k) + len(new_v)) if want_compressed else (new_k.nbytes + new_v.nbytes)  # type: ignore[union-attr]

        if self.tier_usage[target] + new_size > dst_cfg.capacity_bytes:
            return False

        # Commit atomically under the lock.
        self.tier_usage[block.tier] -= block.stored_nbytes
        block.k, block.v = new_k, new_v
        block.compressed = want_compressed
        block.tier = target
        self.tier_usage[target] += new_size
        return True

Promotion and demotion policy

A background sweep at a configurable interval (100 ms is a reasonable start) scores resident blocks by recency and access count. Blocks below the demotion threshold move one tier down; blocks accessed in the last window and resident below HBM are promotion candidates, subject to the prefetch policies in 08 and 09. check_invariants() runs at the end of every sweep in a canary and increments kv_accounting_drift_total on failure; section O2 treats any increment as a drain-and-restart condition.

class CXLAllocator:
    def __init__(self, dax_path: str = "/dev/dax0.0", size_bytes: int = 64 << 30, alignment: int = 2 << 20) -> None:
        self.fd = os.open(dax_path, os.O_RDWR)
        self.size = size_bytes
        self.alignment = alignment  # devdax maps in 2 MiB (or 1 GiB) pages; keep carve-outs aligned
        self.mm = mmap.mmap(self.fd, self.size, flags=mmap.MAP_SHARED, prot=mmap.PROT_READ | mmap.PROT_WRITE)
        self.offset = 0

    def allocate(self, nbytes: int) -> memoryview:
        start = -(-self.offset // self.alignment) * self.alignment  # round up
        if start + nbytes > self.size:
            raise MemoryError(f"CXL region exhausted: need {nbytes} at {start}, size {self.size}")
        self.offset = start + nbytes
        return memoryview(self.mm)[start : start + nbytes]

    def as_array(self, buf: memoryview, dtype: np.dtype, shape: tuple[int, ...]) -> np.ndarray:
        return np.frombuffer(buf, dtype=dtype).reshape(shape)

    def close(self) -> None:
        self.mm.close()
        os.close(self.fd)

KV Store Memory Layout

WhenCustom tiering code that owns its own buffers. Paged engines fix the layout for you; this section is for measuring the tradeoff before writing code that assumes one.
PerformanceAdvanced

Two layouts, one tradeoff

Layer-major keeps one layer's keys for a token range contiguous: attention's read pattern. Token-major keeps all layers for one token contiguous: tier movement's read pattern. Each layout makes one of the two access patterns a strided gather. The class below is numpy-backed so the contiguity test runs in CI; the indexing is identical for a device tensor.

Pythonlayout.py · KVStore
class KVStore:
    def __init__(self, n_layers: int, n_kv_heads: int, head_dim: int, max_seq: int,
                 layout: Layout = "layer_major", dtype: np.dtype = np.dtype(np.float16)) -> None:
        self.layout: Layout = layout
        self.n_layers, self.max_seq = n_layers, max_seq
        if layout == "layer_major":
            self.store = np.zeros((n_layers, 2, max_seq, n_kv_heads, head_dim), dtype=dtype)
        elif layout == "token_major":
            self.store = np.zeros((max_seq, n_layers, 2, n_kv_heads, head_dim), dtype=dtype)
        else:
            raise ValueError(layout)

    def write(self, layer: int, pos: int, k: np.ndarray, v: np.ndarray) -> None:
        if self.layout == "layer_major":
            self.store[layer, 0, pos] = k
            self.store[layer, 1, pos] = v
        else:
            self.store[pos, layer, 0] = k
            self.store[pos, layer, 1] = v

    def read_layer_range(self, layer: int, start: int, end: int) -> tuple[np.ndarray, np.ndarray]:
        """Attention's access pattern. Contiguous in layer-major, strided in token-major."""
        if self.layout == "layer_major":
            return self.store[layer, 0, start:end], self.store[layer, 1, start:end]
        return self.store[start:end, layer, 0], self.store[start:end, layer, 1]

    def read_token_range_all_layers(self, start: int, end: int) -> np.ndarray:
        """Tier movement's access pattern. Contiguous in token-major, strided in layer-major."""
        if self.layout == "token_major":
            return self.store[start:end]
        return np.ascontiguousarray(self.store[:, :, start:end].transpose(2, 0, 1, 3, 4))

    def is_contiguous_for_attention(self, layer: int, start: int, end: int) -> bool:
        k, _ = self.read_layer_range(layer, start, end)
        return k.flags["C_CONTIGUOUS"]
Decision heuristic
Attention runs every step and tier movement runs occasionally, so layer-major is the default. Token-major pays when the tiering rate is high relative to the decode rate: long-context single-stream serving where whole token ranges migrate per step. Measure read_token_range_all_layers on your shapes before choosing it; the gather cost in layer-major is often small enough that the question is moot.

Insertion, Eviction and Access Hooks

WhenTelemetry, compaction triggers, or policy inputs need to observe cache events without being on the critical path.
AdvancedMemory

Hooks are observers

Two rules. A hook must not call back into the cache while the cache lock is held, or it deadlocks; HookedCache runs hooks after the operation completes, outside the lock. A hook must not raise, or a telemetry outage fails requests; exceptions are counted in hook_errors and logged. The compaction hook sets a flag the scheduler reads at its next quiet point rather than compacting inline, for the same reason.

class HookedCache:
    def __init__(self, cache: TieredKVCache) -> None:
        self.cache = cache
        self.hooks: list[CacheHook] = []
        self.hook_errors = 0

    def register(self, hook: CacheHook) -> None:
        self.hooks.append(hook)

    def _emit(self, fn: Callable[[CacheHook], None]) -> None:
        for h in self.hooks:
            try:
                fn(h)
            except Exception:  # noqa: BLE001 - observers must never fail the request
                self.hook_errors += 1
                log.exception("cache hook failed")

    def insert(self, block: KVBlock) -> None:
        self.cache.insert(block)
        self._emit(lambda h: h.on_insert(block, block.tier))

    def evict(self, block_id: int, reason: str) -> KVBlock:
        block = self.cache.remove(block_id)
        self._emit(lambda h: h.on_evict(block, reason))
        return block

    def access(self, block_id: int) -> None:
        self.cache.touch(block_id)
        block = self.cache.blocks[block_id]
        self._emit(lambda h: h.on_access(block))

    def move(self, block_id: int, target: Tier) -> bool:
        src = self.cache.blocks[block_id].tier
        ok = self.cache.move(block_id, target)
        if ok:
            block = self.cache.blocks[block_id]
            self._emit(lambda h: h.on_move(block, src, target))
        return ok

Eviction Scoring Compatible With Fused Attention

WhenT4 eviction is in scope and the quality gate has passed. Scoring must work without a materialized attention matrix.
AdvancedPerformance

The contradiction the earlier edition contained

T1 mandates fused attention kernels (FlashAttention), which never materialize the attention matrix. The earlier edition's eviction policy consumed per-step attention weights of shape [batch, heads, 1, n], which only exist if the kernel materializes them; it also called .cpu().numpy() on every layer of every decode step, forcing a device synchronization inside the loop it was meant to speed up. The two sections could not both be followed. Two policies that work with fused kernels:

Observation window (SnapKV-style)

At the end of prefill, compute attention from the last window query positions to all keys with one small explicit matmul, pool the scores over neighboring positions so that coherent spans stay together, and keep the top budget positions. This is one computation on a short window, not a per-step materialization; decode stays on the fused kernel.

Pythoneviction.py · observation_window_scores
def observation_window_scores(q_window: np.ndarray, keys: np.ndarray, pool: int = 7) -> np.ndarray:
    """Per-position importance from the last ``window`` queries. Shapes:

    q_window: [heads, window, head_dim]
    keys:     [heads, seq_len, head_dim]
    returns:  [seq_len]

    Pooling over neighboring positions keeps locally coherent spans together
    instead of selecting isolated tokens.
    """
    scale = 1.0 / np.sqrt(keys.shape[-1])
    logits = np.einsum("hwd,hsd->hws", q_window, keys) * scale  # [heads, window, seq]
    attn = _softmax(logits, axis=-1)
    scores = attn.sum(axis=(0, 1))  # [seq]
    if pool > 1:
        kernel = np.ones(pool) / pool
        scores = np.convolve(scores, kernel, mode="same")
    return scores

def select_keep(scores: np.ndarray, budget: int, sink: int = 4, recent: int = 64) -> np.ndarray:
    """Indices to retain, sorted ascending. Always includes sink and recent tokens."""
    seq_len = scores.shape[0]
    if budget >= seq_len:
        return np.arange(seq_len)
    protected = set(range(min(sink, seq_len))) | set(range(max(0, seq_len - recent), seq_len))
    if len(protected) >= budget:
        return np.array(sorted(protected))[-budget:]
    free = budget - len(protected)
    candidates = np.array([i for i in range(seq_len) if i not in protected])
    top = candidates[np.argsort(scores[candidates])[::-1][:free]]
    return np.array(sorted(protected | set(top.tolist())))

Sliding Window Prefetch

WhenAny tiered deployment where decode will read positions ahead of the current one from a lower tier. Not specific to sliding-window-attention models.

Prefetch ahead of the decode position

Before each attention computation, schedule promotion of blocks covering the next window_ahead positions that are resident below HBM. Promotion runs on worker threads against the thread-safe tier manager (01). The pending set prevents duplicate promotions and is cleared by the worker's completion callback, never by the caller. The earlier edition described this as being for "windowed attention models (LLaMA, Mistral)"; LLaMA has no sliding window, and the technique is about the memory system, not the attention pattern.

Pythonprefetch.py · SlidingWindowPrefetcher
class SlidingWindowPrefetcher:
    """Promote blocks for the next ``window_ahead`` positions before attention needs them."""

    def __init__(self, cache: TieredKVCache, window_ahead: int = 16, max_workers: int = 4) -> None:
        self.cache = cache
        self.window_ahead = window_ahead
        self._pool = ThreadPoolExecutor(max_workers=max_workers, thread_name_prefix="kv-prefetch")
        self._pending: set[int] = set()
        self._pending_lock = threading.Lock()

    def on_decode_step(self, current_pos: int, layer: int) -> list[Future[bool]]:
        """Schedule promotions. Returns futures so callers can observe completion in tests."""
        futures: list[Future[bool]] = []
        for pos in range(current_pos + 1, current_pos + self.window_ahead + 1):
            block = self.cache.find_block(layer, pos)
            if block is None or block.tier == Tier.HBM:
                continue
            with self._pending_lock:
                if block.block_id in self._pending:
                    continue
                self._pending.add(block.block_id)
            fut = self._pool.submit(self.cache.promote, block.block_id, Tier.HBM)
            fut.add_done_callback(self._done(block.block_id))
            futures.append(fut)
        return futures

    def _done(self, block_id: int):
        def cb(_: Future[bool]) -> None:
            with self._pending_lock:
                self._pending.discard(block_id)

        return cb

    def pending_count(self) -> int:
        with self._pending_lock:
            return len(self._pending)

    def shutdown(self) -> None:
        self._pool.shutdown(wait=True)
Sizing the window
window_ahead × time per decode step must exceed the p99 promotion latency from the tier the blocks live in (section 13 measures it; O1 alerts when it exceeds 50 ms). A window that is too short does not hide the latency; one that is too long evicts useful HBM residents to make room. Gate G6 in O6 checks this arithmetic.

Reuse-Distance Prefetch

WhenAccess patterns recur: agent loops revisiting tool definitions, RAG contexts reused across turns, structured prompts.
I/OAdvanced

Predict the next access from the last few

Track the inter-access distance of each block as an exponential moving average and prefetch when the predicted next access falls within the horizon. The predictor is fed from the access hook (06) and is lock-protected because that hook runs on worker threads.

Pythonprefetch.py · ReuseDistancePredictor
class ReuseDistancePredictor:
    """EMA of inter-access distance per block, used to decide whether to prefetch.

    ``record_access`` is the only writer and is lock-protected so it can be
    called from the hook path (06) on worker threads.
    """

    def __init__(self, ema_alpha: float = 0.3) -> None:
        self.alpha = ema_alpha
        self.last_access: dict[int, int] = {}
        self.predicted_dist: dict[int, float] = {}
        self.step = 0
        self._lock = threading.Lock()

    def record_access(self, block_id: int) -> None:
        with self._lock:
            self.step += 1
            if block_id in self.last_access:
                dist = self.step - self.last_access[block_id]
                prev = self.predicted_dist.get(block_id, float(dist))
                self.predicted_dist[block_id] = self.alpha * dist + (1 - self.alpha) * prev
            self.last_access[block_id] = self.step

    def should_prefetch(self, block_id: int, horizon: int = 8) -> bool:
        with self._lock:
            if block_id not in self.predicted_dist:
                return False
            steps_since = self.step - self.last_access[block_id]
            return (self.predicted_dist[block_id] - steps_since) <= horizon

Non-Blocking NVMe-to-GPU Staging

WhenAny tier below DRAM. A synchronous read on the decode path costs one full step per block.
I/OPerformance

Three stages, two correctness rules

Storage read into a pinned host buffer; optional CPU decompression; asynchronous host-to-device copy on a dedicated CUDA stream. The earlier edition of this pipeline violated two rules. It reused pinned buffers round-robin with no completion tracking, so a buffer could be overwritten while a prior copy was still reading it. And it returned the destination tensor immediately after an asynchronous copy with no event, so the caller received memory whose contents were not yet valid. The rewrite records an event per buffer, waits on it before reuse, and returns the event with the tensor so the consumer's stream can wait on it.

Pythonloader.py · StagedLoader
class StagedLoader:
    def __init__(self, torch_mod: Any, n_buffers: int = 4, buf_size: int = 16 << 20, io_workers: int = 4) -> None:
        self.torch = torch_mod
        self.buf_size = buf_size
        self.streams = [torch_mod.cuda.Stream() for _ in range(n_buffers)]
        self.pin_bufs = [torch_mod.empty(buf_size, dtype=torch_mod.uint8, pin_memory=True) for _ in range(n_buffers)]
        # Event recorded after the last H2D copy that read from each buffer.
        self.buf_free: list[Any] = [None] * n_buffers
        self._next = 0
        self._io = ThreadPoolExecutor(max_workers=io_workers, thread_name_prefix="kv-io")

    def _acquire(self) -> int:
        i = self._next
        self._next = (self._next + 1) % len(self.pin_bufs)
        ev = self.buf_free[i]
        if ev is not None:
            ev.synchronize()  # block until the prior copy from this buffer has retired
        return i

    @staticmethod
    def _pread(path: str, offset: int, size: int) -> bytes:
        fd = os.open(path, os.O_RDONLY)
        try:
            return os.pread(fd, size, offset)
        finally:
            os.close(fd)

    def load_block(self, path: str, offset: int, size: int, decompress: Callable[[bytes], bytes] | None = None) -> Staged:
        if size > self.buf_size:
            raise ValueError(f"block {size} B exceeds pinned buffer {self.buf_size} B")
        raw = self._io.submit(self._pread, path, offset, size).result()
        if decompress is not None:
            raw = decompress(raw)
            if len(raw) > self.buf_size:
                raise ValueError("decompressed block exceeds pinned buffer")

        i = self._acquire()
        buf, stream = self.pin_bufs[i], self.streams[i]
        n = len(raw)
        buf[:n].copy_(self.torch.frombuffer(bytearray(raw), dtype=self.torch.uint8))

        dst = self.torch.empty(n, dtype=self.torch.uint8, device="cuda")
        ready = self.torch.cuda.Event()
        with self.torch.cuda.stream(stream):
            dst.copy_(buf[:n], non_blocking=True)
            ready.record(stream)
        self.buf_free[i] = ready
        return Staged(tensor=dst, ready=ready)

    def shutdown(self) -> None:
        self._io.shutdown(wait=True)

    This is the number that belongs in your capacity model. Published ratios
    were measured on someone else's tensors.

TPOT breach

Likely causes. Decode is bandwidth-bound: too many resident sequences, so each step reads more KV than the bandwidth budget allows; KV spilled to a slower tier and is being read from there; speculative acceptance fell on a new traffic mix so speculation now costs more than it saves.
Diagnose. kv_tier_utilization_ratio; rate of kv_tier_bytes_moved_total into HBM; engine acceptance-length metric.

Prefix hit-rate collapse

Likely causes, in order. A prompt-template regression moved a volatile field ahead of the stable prefix; the router stopped being sticky; the tokenizer or adapter version changed, so keys changed (E1) and the collapse is correct and temporary; the tenant mix shifted toward low-reuse tenants.
Diagnose. Diff the template; check session affinity; compare tokenizer_version and adapter_id across replicas.
Remediate. Revert the template; restore affinity. If a version change, hold and watch the warm-up.

Accounting drift

Meaning. kv_accounting_drift_total incremented: tier usage counters no longer match resident blocks, so every admission decision since is wrong. Not reversible in place.
Remediate. Drain the replica, capture the block table and counters for the defect report, restart. Do not continue serving on a replica with drift.

Cold-start storm

TTFT breach immediately after scale-out, recovering over minutes. Warm new replicas by replaying each tenant's top stable prefixes with max_tokens=1 before admitting traffic, and gate readiness on hit rate, not on process start.

def next_rung(current: Rung, hbm_util: float, tpot_p99_ms: float, slo: SLO) -> Rung:

    breached = hbm_util > 0.92 or tpot_p99_ms > slo.tpot_p99_ms

    return current

Mechanics

def generate_trace(cfg: TraceConfig) -> list[Request]:
    rng = np.random.default_rng(cfg.seed)
    prefix_lens = rng.integers(128, 2048, size=cfg.n_unique_prefixes)

    # MMPP: the OFF rate is set so the long-run mean equals mean_rate_rps.
    p_on = cfg.burst_mean_len_s / (cfg.burst_mean_len_s + cfg.quiet_mean_len_s)
    rate_on = cfg.mean_rate_rps * cfg.burst_factor
    rate_off = max((cfg.mean_rate_rps - p_on * rate_on) / (1 - p_on), cfg.mean_rate_rps * 0.05)

    t = 0.0
    on = False
    state_end = rng.exponential(cfg.quiet_mean_len_s)
    sessions: dict[int, int] = {}  # session_id -> last turn
    trace: list[Request] = []

    for i in range(cfg.n_requests):
        rate = rate_on if on else rate_off
        t += rng.exponential(1.0 / rate)
        while t > state_end:
            on = not on
            state_end += rng.exponential(cfg.burst_mean_len_s if on else cfg.quiet_mean_len_s)

        seq_len = _seq_len(cfg, rng)
        prefix_id = None
        prefix_len = 0
        if rng.random() < cfg.prefix_sharing_ratio:
            prefix_id = int(rng.integers(0, cfg.n_unique_prefixes))
            prefix_len = int(min(prefix_lens[prefix_id], seq_len))

        if sessions and rng.random() < cfg.multi_turn_ratio:
            session_id = int(rng.choice(list(sessions.keys())))
            sessions[session_id] += 1
        else:
            session_id = i
            sessions[session_id] = 1
        trace.append(Request(i, t, seq_len, prefix_id, prefix_len, session_id, sessions[session_id]))
    return trace

class TraceReplayer:
    def __init__(self, strategies: list[CacheStrategy]) -> None:
        self.strategies = strategies
        self.results: dict[str, list[ReplayResult]] = {s.name: [] for s in strategies}

    def replay(self, trace: list[Request]) -> None:
        for s in self.strategies:
            out = self.results[s.name]
            for req in trace:
                t0 = time.perf_counter_ns()
                r = s.on_request(req)
                r.latency_ns = time.perf_counter_ns() - t0
                out.append(r)

    def summary(self) -> dict[str, dict[str, float]]:
        report: dict[str, dict[str, float]] = {}
        for name, rs in self.results.items():
            lat = np.array([r.latency_ns for r in rs], dtype=float)
            report[name] = {
                "hit_rate": sum(r.hit for r in rs) / max(len(rs), 1),
                "p50_us": float(np.percentile(lat, 50)) / 1e3 if len(lat) else 0.0,
                "p99_us": float(np.percentile(lat, 99)) / 1e3 if len(lat) else 0.0,
                "bytes_moved_gb": sum(r.bytes_moved for r in rs) / 1e9,
            }
        return report

    """``sync`` is torch.cuda.synchronize for a real engine; None for the fake."""
    sync = sync or (lambda: None)
    out: list[Cell] = []
    t_start = time.perf_counter()
    for ctx in cfg.context_lengths:
        for bs in cfg.batch_sizes:
            if time.perf_counter() - t_start > cfg.time_budget_s:
                return out
            for _ in range(cfg.warmup):
                engine.run_prefill(ctx, bs)
            pre, dec, preempted = [], [], 0
            util_max: dict[str, float] = {}
            for _ in range(cfg.n_iterations):
                sync()
                t0 = time.perf_counter()
                r = engine.run_prefill(ctx, bs)
                sync()
                t1 = time.perf_counter()
                engine.run_decode(cfg.decode_tokens)
                sync()
                t2 = time.perf_counter()
                pre.append((t1 - t0) * 1e3)
                dec.append((t2 - t1) * 1e3 / cfg.decode_tokens)
                preempted += r.preempted
                for t, u in engine.tier_utilization().items():
                    util_max[t.name] = max(util_max.get(t.name, 0.0), u)
            out.append(Cell(ctx, bs,
                            float(np.percentile(pre, 50)), float(np.percentile(pre, 99)),
                            float(np.percentile(dec, 50)), float(np.percentile(dec, 99)),
                            preempted, util_max))
    return out

def test_sessions_are_isolated(engine: Engine):
    """Deterministic: each session's output is a function of its own (session, prompt) only."""
    errors: list[tuple[int, Exception]] = []
    expected = {i: engine.generate([i] * 16, 8, session_id=f"s{i}") for i in range(16)}

    def session(i: int) -> None:
        try:
            got = engine.generate([i] * 16, 8, session_id=f"s{i}")
            assert got == expected[i]
        except Exception as e:  # noqa: BLE001
            errors.append((i, e))

    threads = [threading.Thread(target=session, args=(i,)) for i in range(16)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    assert not errors

// Section 17. LZ4 compression offload through the Xilinx/AMD Vitis Data Compression
// Library on an Alveo card, driven by XRT.
//
// Hardware-specific. The kernel names, argument order and the output-size side
// channel are properties of the xclbin you build from the Vitis library; the
// ones below follow the library's lz4 streaming example. Build:
//   g++ -std=c++17 -I$XILINX_XRT/include fpga_compress.cpp -L$XILINX_XRT/lib -lxrt_coreutil -o fpga_compress
#include <chrono>
#include <cstdint>
#include <stdexcept>
#include <string>
#include <vector>

#include <ert.h>  // ERT_CMD_STATE_COMPLETED
#include <xrt/xrt_bo.h>
#include <xrt/xrt_device.h>
#include <xrt/xrt_kernel.h>

class FPGACompressor {
    xrt::device device_;
    xrt::kernel compress_kernel_;
    xrt::kernel decompress_kernel_;
    static constexpr size_t kBlockSize = 64 * 1024;  // Vitis LZ4 kernels operate on 64 KiB blocks

public:
    FPGACompressor(const std::string& xclbin_path, unsigned device_idx = 0)
        : device_(device_idx) {
        auto uuid = device_.load_xclbin(xclbin_path);
        compress_kernel_ = xrt::kernel(device_, uuid, "xilLz4Compress");
        decompress_kernel_ = xrt::kernel(device_, uuid, "xilLz4Decompress");
    }

    // Returns the compressed bytes. Throws on XRT errors; callers fall back to the CPU codec.
    std::vector<uint8_t> compress(const uint8_t* data, size_t len) {
        if (len == 0) return {};
        // LZ4 worst case is input + input/255 + 16; allocate that so the kernel can never overrun.
        const size_t out_cap = len + len / 255 + 16;

        auto in_bo  = xrt::bo(device_, len,              compress_kernel_.group_id(0));
        auto out_bo = xrt::bo(device_, out_cap,          compress_kernel_.group_id(1));
        auto sz_bo  = xrt::bo(device_, sizeof(uint32_t), compress_kernel_.group_id(2));  // output size

        in_bo.write(data);
        in_bo.sync(XCL_BO_SYNC_BO_TO_DEVICE);

        auto run = compress_kernel_(in_bo, out_bo, sz_bo, static_cast<uint32_t>(len), static_cast<uint32_t>(kBlockSize));
        if (run.wait(std::chrono::seconds(5)) != ERT_CMD_STATE_COMPLETED) {
            throw std::runtime_error("xilLz4Compress did not complete");
        }

        sz_bo.sync(XCL_BO_SYNC_BO_FROM_DEVICE);
        uint32_t compressed_size = 0;
        sz_bo.read(&compressed_size);
        if (compressed_size == 0 || compressed_size > out_cap) {
            throw std::runtime_error("xilLz4Compress reported an invalid output size");
        }

        out_bo.sync(XCL_BO_SYNC_BO_FROM_DEVICE);
        std::vector<uint8_t> result(compressed_size);
        out_bo.read(result.data(), compressed_size, 0);
        return result;
    }
};

Fallback is mandatory: on any XRT error the tier manager uses the CPU codec (11). A compression offload that can fail a request has negative value.

Research Horizon: Programmable KV Scoring in Storage

WhenNot for production. Included so that the idea is evaluated against what exists rather than assumed.
Advanced
Status
The earlier edition presented this as implementation step 18 with code for uploading an eBPF program or FPGA bitstream into an SSD controller to score KV blocks in place. No shipping product exposes that capability through a stable interface. Computational storage exists (NVMe Computational Programs is a standards effort; vendor SmartSSD parts with FPGAs have shipped), but a KV-scoring kernel inside the drive is a research direction, not a deployable technique.

What the idea is

Instead of reading all candidate KV blocks to the host to decide which are relevant, the drive evaluates a scoring function against a query and returns only the top-k block identifiers. For large candidate sets this would reduce PCIe traffic by the ratio of candidates to winners.

What would need to be true

  • A standardized way to load and invoke a program on the drive (the NVMe Computational Programs work), supported by your drives and your kernel.
  • A scoring function cheap enough to run at drive-controller speeds; attention-derived scores (07) are not, key-norm proxies might be.
  • A security model: a program running inside a drive that holds multiple tenants' blocks (E1, E2) is inside the authorization boundary.

Until those hold, the production answer to the same problem is the observation-window selection in 07 at prefill time, which decides what to keep before anything is written to the drive.
